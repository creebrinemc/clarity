# Clarity 0.6.0 Release Notes

Clarity **0.6.0** transforms Clarity from a single-file scripting language into a multi-file, project-aware language with a built-in test runner and standalone Windows installer support.

> **Release Timing Note:** Clarity `0.6.0` was feature-complete roughly six weeks prior to this public release; final publication was simply delayed by an administrative oversight rather than six additional weeks of changes. We are publishing `0.6.0` cleanly as its own milestone ahead of `0.7.0`.

---

## Highlights

### 1. Modules & Imports
Organize programs across files with explicit quoted paths:
```clr
import "utils/formatting" as fmt
from "math_helpers" import square and cube

say fmt.format_name("alice")
say square(4)
```
- **Encapsulation**: Top-level declarations are exported by default; names starting with `_` are private to their module.
- **Caching & Cycle Detection**: Modules execute once per program in isolated top-level scopes, and circular imports produce a `Clarity Circular Import Error` showing the dependency chain.

### 2. Dot Member Access
Access module exports and dictionary keys using `target.member`:
```clr
set user to { name: "Creebrine", score: 100 }
say user.name
```
*(Dictionary dot access is read-only; continue using `set user["score"] to ...` for updates.)*

### 3. Static `conf.clr` Project Manifest & CLI
Create, run, and test multi-file Clarity projects:
```bash
clarity new my-app
cd my-app
clarity run
clarity test
```
- `conf.clr` uses native Clarity dictionary literal syntax (`set project to { ... }`) and is validated statically at the AST level without arbitrary code execution.
- Single-file script execution (`clarity script.clr`) and `clarity --version` remain 100% backward-compatible.

### 4. Native Test Runner & Assertions
- `clarity test [path]` discovers `*_test.clr` and `test_*.clr` files and executes top-level `test_*` functions.
- Built-in assertion functions: `assert(condition [, message])` and `assert_equal(actual, expected [, message])`.

### 5. Standalone Runtime & Windows Installer
- **Windows x64 Installer**: `Clarity-0.6.0-Windows-x64-Setup.exe` (compiled via PyInstaller + Inno Setup 6 in GitHub Actions) bundles a standalone runtime with optional `PATH` setup and `.clr` file associations. No Python installation is required for Windows installer users.
- **Portable Windows Bundle**: `Clarity-Windows-x64-Portable` artifact built alongside the installer.

---

## Compatibility Notes

- **Reserved keywords**: `import` and `as` are now reserved keywords and cannot be used as variable or function names.
- **Dictionary dot assignment**: `set dict.key to value` is not supported in `0.6.0`; use `set dict["key"] to value`.
- **Single-file scripts**: Existing `0.5.0` scripts run without `conf.clr` unless they use `import` or `as` as identifiers.

## Installation

### Windows
Download `Clarity-0.6.0-Windows-x64-Setup.exe` from the release assets and run the installer, then open a new terminal:
```powershell
clarity --version
# Output: Clarity 0.6.0
```

### From Source (macOS, Linux, Windows — Python 3.11+)
```bash
git clone https://github.com/creebrinemc/clarity.git
cd clarity
python3 -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]"
clarity --version
```
